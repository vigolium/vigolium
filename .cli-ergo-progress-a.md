## Deviations

- F6/SHOT-4: format inference runs first, so under -j an -o whose extension names a scan format (`-j -o r.html`) is still the base path for that format; -o names the document when no format was given or inferred (`-j -o doc`, `-j -o doc.json`), or when it ends in .json (`-j --format html -o r.json` writes r.json = document and r.html). The document file is probed for writability before the run.
- SHOT-3: the preflight failure is `export_failed` (exit 1), the code the same unwritable path carried after the scan, not a usage error. A -S run whose error is export_failed/pdf_failed keeps its working database (moved to ~/.vigolium/recovered, path in the error) without --keep-db-on-error.
- SHOT-1: `--silent` finding lines are suppressed when -j, --events or a stdout jsonl/github stream owns stdout. The direct scan-url/scan-request path under --silent prints the same lines and no completion line. `--ci-output-format` is hidden and rejected in the root PersistentPreRunE (exit 2, hint names -j and --format jsonl); it is no longer recovered as a presentation flag, so the refusal is human text unless -j is also given. The remaining `globalCIOutput` reads (banner, color, update check) are now always false and were left in place.
- SHOT-5: one evidence record per finding (records_total/records_truncated say when there were more), not --record-limit's 20: the scan document has up to 200 items. Record UUIDs are dropped unless a sqlite artifact was written or the working DB is kept (--keep-db-on-error with a failure, or an export failure).
- SHOT-8: `estimate.duration_ms {low, high, basis, confidence}` (a nested object, not a bare number, so the existing `duration_ms` naming convention holds the range). Phases with no rate limit assume 50 req/s, said in the basis. The banner appends `~low-high (rough)` to the Estimate line; scan.started carries it inside the plan.
- SHOT-10: the line is printed in the first-run notice (the one place that names `doctor --fix`), names the variable it saw and the matching `--agent` (claude/codex/agents); doctor's "not installed (optional)" check is unchanged.
- F7: `pkg/http/proxyenv.Resolve(cli, getenv) Choice` with `For(url)`, `Func()`, `Proxies()`, `Routes()`, `Describe(target)`, `Summary()`. `--proxy` and VIGOLIUM_PROXY (which the CLI copies into the flag value; named as its own source) proxy everything and ignore NO_PROXY. The Requester's scan, no-redirect, h2-fallback and login transports, replay's default client and portsweep's confirm step use it; the raw client is a set (direct + one per proxy URL) picked per request, since rawhttp dials through its client's proxy. Other ProxyFromEnvironment users (spec loader, nuclei template download, dependency-confusion registry, server ingest proxy, runner infra client) talk to third parties, not the target, and were left alone.
- SHOT-6: decision 5 applied — environment proxies are now chosen by target scheme, so `HTTP_PROXY=<Burp>` alone no longer proxies https targets (use HTTPS_PROXY or ALL_PROXY); the usage example now uses ALL_PROXY. Plan gains `proxy {routes[], no_proxy, no_proxy_source, targets{}}`; banner prints `Proxy:`; the unreachable error (runner and direct path) names the proxy and its variable; doctor `--for scan` checks env proxies too (message names the source, NO_PROXY and that loopback is not bypassed) and probes a NO_PROXY target directly.
- SHOT-7: verified MISS-22/23 do not cover resets: under the default WAF-auto-arm limiter an unarmed host ignores ordinary distress, so a dev server's reset storm only counted toward quarantine. Added: 3 consecutive connection resets (ECONNRESET/EPIPE/unexpected EOF, counter cleared by any answer) arm the host and the distress path halves it; `HostRateLimiter.PreArmLocalTarget(targets)` pre-arms the single loopback/private host (vendor "local", own notice text) in the runner and on the direct scan-url/scan-request path. Both pre-arms obey --no-waf-pacing (PreArmable).
- SEND-1: the run filter is `scan_uuid = <this scan> OR uuid IN <seeds>` (`database.RunRecordFilter`), not `created_at >= since`: records carry the scan that wrote them, which is exact and immune to concurrent writers; seeds are the records the seed/discovery executors stored or deduplicated onto (OnRecordStored), narrowed to those another scan wrote. Applied to the dynamic-assessment source (every round) and param-mining candidates. KIS, discovery, respider and route seeds read host-level origins (or SPA routes), not records to attack, and were left as is. `Options.StoredRecords` "", "include", "exclude": scan-url/scan-request always exclude unless --include-stored (Runner path; the direct path never read stored records); run excludes when -t/-T is given unless --include-stored; scan includes unless --input-only. Plan gains `targets.stored_records` and `targets.db_records_excluded` (db_records_in_scope is 0 under exclude, so the estimate follows); the banner states the stored count and which flag flips it.
- SHOT-9: both paths print the Runner's resolved plan (resolveCLIScanPlan over buildPhaseOptions + resolveLightweightScanOptions, i.e. what scan.started would carry) with a new `plan.execution_path` ("runner"|"direct"); the direct path adds a `direct_path` warning naming what it skips and which flags would switch to the runner, instead of a separate small plan shape, so one schema covers both. scan-request skips the scheme probe under --dry-run.
- F8/SEND-5: new code `out_of_scope` (exit 2; classifyExitCode/classifyErrorCode keep the code at exit 2). `sendScopeGate` (pkg/cli/send_scope.go) over config.NewScopeMatcher(settings.Scope, -t targets) checks every destination before the first send; bulk replay/traffic --replay refuse the whole batch when any record's host is out of scope (records are already in memory, so it costs nothing). fuzz's scope refusal moves from exit 1 `failed` to exit 2 `out_of_scope`, dns's from `usage_error` to `out_of_scope`. New `--ignore-scope` on replay, traffic (with --replay), kit param-mine, finding verify (fuzz and dns had it). finding verify --dry-run is not gated (sends nothing).
- F9/SEND-8: `pkg/requestinput.Parse(ctx, text, Options{Target, NoProbe, Resolver})` = Normalize (bodyless requests get exactly one header terminator; body-bearing ones are kept verbatim) + ParseRawRequest(WithURL) + requestscheme.Settle. Used by replay/fuzz -i for raw HTTP text (other input types still go through the agent normalizer; a raw text that fails here falls back to it) and by scan-request's normalization (its scheme settle was already requestscheme.Settle, so its flow is unchanged). replay/fuzz probe the scheme only after the scope gate admits the host. Ingest: no scheme probe (a format parser should not touch the network); instead `-t` rebases a burpraw file (burpraw.SetBaseURL via ApplySpecOptions) and an auto-detected raw/Burp-pair input, and is no longer added as a separate target. SEND-4's replay path needed no change (it already compares bytes before sending).
