## Deviations

- F5: `yamledit.EditFile(path, func(*yamledit.Doc) error, Options)` instead of `func(*yaml.Node)`: the helpers (`Set`, `Delete`, `AppendUnique`, `RemoveItems`) are methods on `Doc` because they record which source span they changed. Every splice is re-parsed and compared with the edited tree; on any mismatch the whole tree is re-encoded (comments kept, blank lines lost), so a splice bug can cost formatting but never content.
- A missing config file is created holding only the edited keys (not the full marshalled Settings), so defaults are not frozen into it. `SaveSettings` now has no callers outside first-time generation; the unused `SaveProjectConfig` was removed.
- `config set -j` `items[].value` is now the value read back from the file (redacted when sensitive), not the argument.
- N-2: dynamic-assessment has no phase-local rate (config.PhasePaceSupports), so `--rate-limit dynamic-assessment=N` stays unenforced; the plan's per-phase pace and the scan.started pace table now report the scan-wide limit for that phase instead of 0. The direct scan-url/scan-request path has no plan or speed banner line, so its effective rate shows only through the Runner path's plan.
- DATA-1: per-table counts come from a context-carried counter the shared delete helpers feed, and every dry run executes the delete in a transaction and rolls it back. `rows_matched`/`rows_deleted` are now totals over every table touched (they were the main table only on scoped modes); `items[]` lists the mode's table first. A records delete now also removes the history rows (observations, status events, hash aliases) of the findings it drops, which it used to leave dangling. flags.generated.md regenerated in the same commit (help text of --all/--severity).
- SEND-2: deny-lists are two keys, `dynamic-assessment.enabled_modules.disabled_active_modules` / `disabled_passive_modules` (fields `DisabledActiveModules`/`DisabledPassiveModules`). They subtract only from an "all" selection; an explicit `-m` naming a disabled module still runs it. The empty-allow-list rule is a `config validate` error keyed on the list (so `config set … []` is refused); at scan time an empty list still behaves as before rather than failing scans of existing configs. `--force` threshold applies to enable and disable alike.
- SEND-3: a marker combined with ANY of `--point`/`--fuzz`/`--fuzz-header` is a usage error (all three were silently overridden by the marker, not only `--point`). Synthetic header filtering is done in `fuzz.ResolvePositions` (drops INS_HEADER points whose header is absent from the request) rather than via a new httpmsg option, so the scanner's insertion points are untouched; `--fuzz-header Name` for an absent header still works. `--max-requests` refuses an over-cap plan (exit 2) instead of truncating it, since there is no `Job.MaxCases` field and a silent truncation would lose coverage; it counts payload sends only. The MISS-38 baseline-unreachable abort already existed and was left as is. Skill/docs examples that relied on the implicit "all insertion points" now pass `--fuzz params`.
- SEND-4: implemented inside `replay.Do` without F9 (Wave 3): when the request to send is byte-identical to `BaselineRequest`, no stored response exists and `Options.SendBaseline` is false, it is sent once and `baseline`/`diff` are null (already nullable in the schema). New `replay --baseline` sets it. The olium `replay_request` tool sets `SendBaseline` so its output keeps a diff. Human output shows a one-column table with a hint.
- AGENT-1: autopilot `--dry-run` returns from `runAgentAutopilot` before `runAutopilotOlium` (session dir, run row, prior context, knowledge base, preflight, pre-scan and the audit pipeline are all skipped) and prints `{target, source_path, focus, system_prompt, initial_prompt, note}` via `autopilot.RenderPrompts` (the new export); the provider is not resolved, so a claude-code persona is not reflected. Burp-bridge import and gs:// download are skipped too. Swarm under DryRun skips input probing, auth, discovery and recon; the plan phase already rendered prompts via the engine's DryRun. The natural-language path under `--dry-run` returns before the guardrail and the intent model call: a URL prompt resolves offline (`agent.StructuredIntent`), anything else is reported `model_parsed:false`. `printIntentDryRun` removed (and its stdout-baseline entry).
- SRV-1: `server.Server.Bind()` opens both listeners (`net.Listen("tcp", …)`) and `Start` serves them (`fiber.App.Listener`, `http.Server.Serve`); the CLI binds right after constructing the server, before either banner, and returns the bind error (exit 1). A serve error after startup now also makes the command return an error instead of nil.
- SRV-4: `server.CheckAPIBind(host, noAuth, allow)` beside `CheckProxyBind`, applied right after `resolveServerHost` (so `$VIGOLIUM_SERVER_HOST=0.0.0.0` from the Docker images counts); usage error, exit 2. New flag `--allow-unauthenticated-bind`. No exemption for `--view-only`/`--demo-only`.
- DATA-2/F10: `pkg/cli/export_types.go` holds the record-type table (canonical name, envelope type, aliases, importable, implicitly-excluded) — the format-support column and `exportQuery` are left to Wave 4. `exportScope` now carries `only` and `exclude` in canonical names; `--exclude` defaults to nothing and the module registry is excluded by the table's implicit rule. `vigolium export --format jsonl` uses the export command's scope (it used the scan's `--export-only` scope); post-scan jsonl keeps `scanExportScope`. A type named in both `--only` and `--exclude` is exit 2. csv/sarif with no findings in scope is exit 2.
