## Deviations

- F5: `yamledit.EditFile(path, func(*yamledit.Doc) error, Options)` instead of `func(*yaml.Node)`: the helpers (`Set`, `Delete`, `AppendUnique`, `RemoveItems`) are methods on `Doc` because they record which source span they changed. Every splice is re-parsed and compared with the edited tree; on any mismatch the whole tree is re-encoded (comments kept, blank lines lost), so a splice bug can cost formatting but never content.
- A missing config file is created holding only the edited keys (not the full marshalled Settings), so defaults are not frozen into it. `SaveSettings` now has no callers outside first-time generation; the unused `SaveProjectConfig` was removed.
- `config set -j` `items[].value` is now the value read back from the file (redacted when sensitive), not the argument.
- N-2: dynamic-assessment has no phase-local rate (config.PhasePaceSupports), so `--rate-limit dynamic-assessment=N` stays unenforced; the plan's per-phase pace and the scan.started pace table now report the scan-wide limit for that phase instead of 0. The direct scan-url/scan-request path has no plan or speed banner line, so its effective rate shows only through the Runner path's plan.
- DATA-1: per-table counts come from a context-carried counter the shared delete helpers feed, and every dry run executes the delete in a transaction and rolls it back. `rows_matched`/`rows_deleted` are now totals over every table touched (they were the main table only on scoped modes); `items[]` lists the mode's table first. A records delete now also removes the history rows (observations, status events, hash aliases) of the findings it drops, which it used to leave dangling. flags.generated.md regenerated in the same commit (help text of --all/--severity).
