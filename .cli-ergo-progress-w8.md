## Deviations

- F4: `commandTraits` (pkg/cli/command_traits.go) is the one table; `machineKinds`, `dbIntents` and `sendsTrafficCommands` are derived maps (same names, so every consumer and test kept working), `MachineContractCommands()` reads them. `Shape.Vocab` nil means "the registered contract item's keys (plus variants)"; commands with no registered item and no `vocabFrom(T{})` validate `--fields` at emit time against the item type's JSON keys (or the emitted rows' keys) — the static test requires a static vocabulary for every generically shaped command that sends traffic, so "validate before any send" holds. `Own` means the command projects its own rows; generic paging still applies to an own command when it did not register -n/--offset itself (none today after the paging decisions below). Paging none (with the TRUTH-12 reasons) for `dns`, `fuzz` (SIZE-5 adds its own -n), `match-not-found`, the scan family. Objects get `--fields` only. Generic validation runs in the root PersistentPreRunE; `activeShaping` carries what the invoked command registered generically, and `applyGenericShaping` uses the trait of the document's `command` (so bare `log`, which prints the `log ls` document, is shaped by `log ls`'s own code).
- F4: the e2e matrix was missing rows for 17 Track C commands (TestMachineContractMatrixCoversEveryLeaf failed); rows added (agent cancel / scan stop / server stop skipped with reasons). `server status -j`'s `running` extra was not in its schema: `serverStatusExtras` registered.
- SIZE-3: "drop" means the value is emptied to null, not the key removed, wherever the schema requires the key (scan document `plan`/`targets`/`phase_outcomes`, `scan status` item `plan`): every compact or budgeted document still validates and no key a parser reads disappears. The budget empties the envelope's `droppable` keys (set by the scan document builder) one at a time, only until the whole document fits, before cutting any finding; `output_budget.dropped_keys` lists them. `--compact` drops `query` (keeps `query_argv`), `generated_at` (keeps `_ms`), the envelope `db_path`, and nulls a scan document's `plan` (a dry run's plan is its answer and stays). `scan status` gets `--fields`/`--compact` through its trait (object with CompactDrop).
