## Deviations

- F10: the format-support column is `exportRecordType.Formats` (empty = every format). `validateExportFormatsScope` now refuses any format that renders none of the in-scope types (not only csv/sarif) and warns on stderr when `--only` names a type a format leaves out. `exportQuery` also carries `from`/`to` (used by DATA-12).
- DATA-5: the `is_authenticated` round-trip claim did not reproduce: a JSONL export keeps `is_authenticated:true` and `import` stores it (locked by `TestExportImportRoundTripKeepsIsAuthenticated`). Scans dedup on uuid, OAST interactions on (project, full_id, protocol, interacted_at), scopes on (project, rule_type, name, host/path pattern); an imported interaction's `finding_id` is dropped (finding ids are local to a store). `-j` also gains `duplicates_by_type`. Unknown/unstored types are counted in `skipped_types` and warned about in human mode; they do not fail the import.
- DATA-6: the new jsonl writer reuses the export envelope, encoder and record-type table but not `streamExportData`: db export's selection is its own `QueryFilters` (host/method/status/path/scan/uuid/limit/offset) and findings are those linked to the selected page, which the export query does not express. `--table` maps http_records/findings onto the line types; any other table is exit 2 naming `export --only`; `--table findings` with a records-only format is exit 2. New format `nuclei` (db export only).
- DATA-9: the agent finding hash gains `|<url>` only when the finding has a URL, so existing code-finding hashes are unchanged. Parse failures and bad severities are `input_unparsed` (exit 1) rather than a usage error: the command line was fine, the data was not.
- DATA-10: a single-source import keeps its bare error; only multi-source runs continue. The partial-failure exit is 1 with code `failed` (not the incomplete class 5), per the spec. `import`'s `db_path` now names the destination. The foreign-SQLite refusal lives in the merge (`database.ForeignStoreError`, code source_incompatible), so `--glob-db` reads skip such a file with a warning too.
- DATA-11: rows written are counted as the project's http_records count after minus before (a save that hits an existing exchange returns its uuid, so per-save counting cannot tell); `records_ingested` keeps its meaning (records now in the store because of this run).
- DATA-12: `db clean --before` is untouched (no `--to` alias). `log ls --from/--to` filters the listed sessions in memory by start time (the listing already reads at most 200 scans). `export --from/--to` bounds each type by its own timestamp; scopes and modules have none and are unaffected.
- F12/DATA-8: `database.ParseHostFilter` returns {Host, Port, Scheme}; an origin without a port means the scheme default (the stored row has it). Applied in the record builder, the findings builder (through the linked-record EXISTS), the endpoint inventory (hostname only: findings have no port/scheme column) and host observations (hostname + port).
- DATA-7: done in the merge ATTACH (`attachMergeSource`), which is the only glob read that wrote sidecars; the per-file `openGlobSourceFile` and `-S` already go through `openSQLiteReadOnly`, which reclaims what it created. The mode=ro fallback is chosen by probing the first read, not by testing directory permissions.
- DATA-13: `db ls`/`db stats`/`scan diff` render TSV from the rows their -j document carries (`readTSV` makes `writeAgentJSON` print the items as TSV; nested objects flatten to dotted columns, arrays JSON-encoded; columns are `--fields` or every key, sorted); `log ls` uses its rowShaping with default columns. The ratchet (`TestTSVReadCommandsRatchet`) pins the set of commands registering `--no-header`. `log <prefix>` resolves against scans and agentic_scans (F13) in the effective project; no match passes through to the session-directory lookup. `db clean --all --dry-run` without --force was already fixed by DATA-1 (w0).
