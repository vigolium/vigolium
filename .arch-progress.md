## Deviations

- SAFE-10: fastdialer classifies "connection refused" as ErrKindNetworkPermanent, so the base retry rule (CheckRecoverableErrors) never retried a refused dial before or after. Kept that; the "not written → retry any method" branch is pinned by a decision-table unit test (TestRetry_SafeToRetryDecision) instead of a refuse-first server. RetryTimeouts set on preflight + heuristics root fetch.
- SAFE-2: Services.HopScope is a plain func field (Services is copied by value in the probe phase, so no atomic); runner builds the scope matcher before NewRequester so it is set before any traffic. The redirect policy reads it per hop.

- SAFE-4: implemented for `vigolium scan`/`run` with -i (deriveFileInputScope before --dry-run; plan.scope gains scope_targets/input_hosts). `ingest --scan-on-receive` derives ScopeTargets from the ingested file (ingestScanScope). REST has no direct file-scan endpoint: file content arrives via POST /api/ingest-http and is scanned by the server's scan-on-receive, so the REST ingest scopes a multi-host capture (HAR/Burp/Postman/OpenAPI without `url`) to its first record's host and stores other hosts with the new source `ingest-context` (not in IngestRecordSources, never fetched or fed to scan-on-receive); response gains `derived_scope` and `context_only`. Bridge pushes (Burp/Caido) and `scope_origin: all` projects are not derived. admission.go/scan_admission.go unchanged: ScopeTargets are only set when there are no -t seeds, so seed admission never sees them. Target-list inputs (-I urls, burpscope) and OpenAPI with explicit --spec-url scope to every census host. OpenAPI without -t now uses servers[0] as base URL unless --spec-url or --scope-origin all.

- SAFE-8: nuclei templates are not filtered per HTTP method (no per-request method filter in the template API); tag exclusion is the enforcement. Executor gate is in executor_worker (before runActiveStage) rather than computeEligibility (which modules with custom CanProcess bypass), counted on the Executor.

- SAFE-3: InstallCredentialRouter signature is (headers, allow, methodAllowed, patterns) — the method filter and Fetch patterns are explicit parameters. Auto-attached targets (iframes/workers in other sessions) are not routed (their requests carry no extra headers anyway since setExtraHTTPHeaders is no longer used). Crawler withdraw path is now a router policy update (allow returns false once withdrawn).

- SAFE-11: no `--resolvers` CLI flag exists; types.Options.Resolvers added (explicit list wins) but not exposed as a flag. Offline is applied per-run by the runner (applyOffline) and the update check reads the root --offline flag only (settings key not consulted there).

- SAFE-12: report extra-redaction names are the operator -H names only (live-session header names are not known at CLI report time; Authorization/Cookie/*-token/*-key are in the built-in table anyway). Runner notifier gets -H names likewise. SARIF test TestSARIFWebRequestAndResponseParsed now expects redacted Set-Cookie values.

- SAFE-14: scope check is enforced through a WithHostFilter requester view installed by jsext.NewEngine (covers plain, session and batch extension HTTP without changing every call signature) instead of a check inside doRawRequest. sandbox_dir empty = cwd changed existing tests that relied on "anywhere" (they now pass SandboxDir).

- ECON-9: WaitStable settle cap 3s (counted, browser.StableCapHits); resource blocking (fonts/media/third-party images) via the shared Fetch interceptor (config BlockResources default true; browser.ResourcesBlocked); host parallelism default 2 for both the re-spider and the INITIAL spidering phase: host groups run through runHostGroups (shared with VIGOLIUM_SPIDER_HOST_PARALLELISM), each group's phase-shared bookkeeping is done under one mutex that is released around the browser work (session open, crawl, session close); skipped-target accounting moved after all groups return.

- MISS-28a: states with fewer than 30 elements get StructID 0 and never fold (small DOMs differ mostly in text, which SimHash ignores — a wizard step must not fold into the previous one). MISS-28d uses SameStructure (exact or structural clone) rather than exact-hash equality so a clone-folded target still verifies.

- MISS-29: (a) popups get up to 2s to load before CloseOtherWindows; in-scope popup URLs are recorded and, after the main crawl loop, browsed into the graph (crawlPopupSeeds via checkOnURLState) and explored by another crawl loop, up to 3 rounds (Stats.PopupSeedsCrawled). (b) response-body fetches run on a 4-worker pool (queue 256; a full queue falls back to an inline fetch, nothing dropped), drained in Close before the request-body workers; provisional/upgradeable hashes and bodies_failed as before. (c) the drain check stops scheduling states DrainGrace+min(45s, MaxDuration/10) before the deadline when the no-navigation DOM-XSS prefilter already has candidates (memoized; re-run at most every 2s).

- MISS-26: spitolas.AuthMonitor is {Observe, Credentials, Changed}. The capture feeds in-scope document/XHR/fetch responses to Observe (network.Capture.OnResponse); Changed is a coalescing channel the runner signals on every successful LiveSession re-login (Runner.relogins broadcast); the crawler marks itself auth-dirty and re-applies credentials at the top of the next action and at the start of followPath. Logout landing detection (login URL / login-form body) with one re-apply + reload, else AuthState=lost and ReasonAuthLost. Authenticated crawls never click logout controls.

- MISS-22: a throttle without Retry-After pauses 1s, 2s, 4s, 4s and then stops pausing (ratelimit.maxPausedThrottles=4; streak resets on a healthy response); transparent retries stop once the streak exceeds 3. The spec's uncapped 1s·2^n up to 60s per throttle stalled a scan of an always-429 host for minutes per module call (ssrf_detection's 429 fixture hit the 10m test timeout). An explicit Retry-After is still honoured up to 60s. ratelimit.ThrottleStreak added.
- Ran `make swagger` (docs/development/api-swagger.json, pkg/server/swagger_spec.json) for ScopeConfig.methods; integrator should regenerate again after merging.
