## Deviations

- F14: no schema version bump. v6 already landed; the three columns are nullable with no backfill, so they ride the ungated column migrations (the surface_score precedent) and are listed under v6's history note. Bumping to 7 would also have broken the v6 one-time relabel tests that stamp `currentSchemaVersion-1`. The columns are NOT on the bun models: `UpdateAgenticScan` (OmitZero model update) and other whole-model writes would otherwise write a stale value back; `pkg/database/stop_requests.go` reads/writes them by column.
- F14: the heartbeat polls the stop request after each periodic beat (10 s), so a stop lands within ~one interval. The direct scan-url/scan-request path (no Runner) handles a stop request by sending os.Interrupt to its own pid (safe: our own process), which reuses the invocation's one signal context; the outcome then reads "stopped on request (<by>)", exit 5 code `interrupted`.

- VERB-1: `scan stop` on an already-finished scan is exit 0 `changed:false action:already_finished` (not an error). `--wait` (default `--timeout 60s`) that is not acknowledged is exit 1 `wait_timeout` with the document kept and `hint` naming `kill -INT <pid>` (only when the scan's host is this host). `scan ls` is a real subcommand sharing `log ls`'s flag variables (AddFlagSet) with alias `list`; `scan ps` stays a verb-rejection pointing at `scan ls`. REST `POST /api/scans/:uuid/stop` for a running scan the server does not own returns 202 `status:"stop_requested"` (409 otherwise, unchanged).

- AGENT-3: the cancel watcher also honours a `cancel` sentinel in the run's session directory (so `agent cancel` reaches a `-S` run whose row is in a temp DB). `agent cancel` of a finished run is exit 0 `changed:false action:already_finished`; `--wait` timeout is exit 1 `wait_timeout`. A run stopped by a cancel request is stored `cancelled` and exits 1 ("agent run cancelled: cancel requested"), matching the existing cancelled→exit 1 vocabulary. `audit --max-cost-usd` / `--token-budget` are registered hidden and always rejected (exit 2) with the reason (drivers report usage only at the end). `audit --dry-run` prints `{driver, modes, audit_modes, piolium_modes, source, agent, sessions_dir, max_duration_ms, driver_check, interactive, note}` (emitObject, like autopilot's dry run); no clone, no session dir, no store. Error envelope gains top-level `agentic_scan_uuid` (contract.ErrorEnvelope mirrored). REST `POST /api/agent/scans/:uuid/cancel` for a run the server does not own returns 202 `cancel_requested` (404 otherwise, unchanged).

- VERB-2: `status` uses a local proxy seam `statusProxyResolver(cliProxy) (url, source)` (flag → HTTP_PROXY/http_proxy/HTTPS_PROXY/https_proxy, the order pkg/http's getProxyURL uses today); credentials redacted. Scope counts are non-default include/exclude counts per component from the global config (as `scope view` reads it).

- VERB-5: `NewUUIDListDBInputSource` alone does not restrict anything — the dynamic assessment reads the store through `RiskPrioritizedDBInputSource`. New `types.Options.RecordUUIDs` restricts that source (`WithRecordUUIDs`, param-shape coalescing off for named records); `scan --record-uuid` (repeatable StringArray, comma lists, 8+ char prefixes via `ResolveRecordUUIDInProject`) goes through the `--all-records` rescan path with `--only dynamic-assessment` unless `--only/--skip` were given. Evidence records (EvidenceRecordSources) are refused (exit 2) rather than silently dropped. Conflicts: -t, -T, -i, --all-records, -S, --db-isolate (exit 2). No `-u` shorthand on scan (decision 8's `-u` alias is FLAG-1, Wave 8). REST `POST /api/scan/records` now also sets `RecordUUIDs` — it assessed every project record before. Found and fixed a W1 regression: `RunNativeScan` dereferenced a nil admission (`admission.Admitted`) on any target-less scan (`--all-records` panicked).
