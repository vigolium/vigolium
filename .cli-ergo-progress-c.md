## Deviations

- F14: no schema version bump. v6 already landed; the three columns are nullable with no backfill, so they ride the ungated column migrations (the surface_score precedent) and are listed under v6's history note. Bumping to 7 would also have broken the v6 one-time relabel tests that stamp `currentSchemaVersion-1`. The columns are NOT on the bun models: `UpdateAgenticScan` (OmitZero model update) and other whole-model writes would otherwise write a stale value back; `pkg/database/stop_requests.go` reads/writes them by column.
- F14: the heartbeat polls the stop request after each periodic beat (10 s), so a stop lands within ~one interval. The direct scan-url/scan-request path (no Runner) handles a stop request by sending os.Interrupt to its own pid (safe: our own process), which reuses the invocation's one signal context; the outcome then reads "stopped on request (<by>)", exit 5 code `interrupted`.

- VERB-1: `scan stop` on an already-finished scan is exit 0 `changed:false action:already_finished` (not an error). `--wait` (default `--timeout 60s`) that is not acknowledged is exit 1 `wait_timeout` with the document kept and `hint` naming `kill -INT <pid>` (only when the scan's host is this host). `scan ls` is a real subcommand sharing `log ls`'s flag variables (AddFlagSet) with alias `list`; `scan ps` stays a verb-rejection pointing at `scan ls`. REST `POST /api/scans/:uuid/stop` for a running scan the server does not own returns 202 `status:"stop_requested"` (409 otherwise, unchanged).

- AGENT-3: the cancel watcher also honours a `cancel` sentinel in the run's session directory (so `agent cancel` reaches a `-S` run whose row is in a temp DB). `agent cancel` of a finished run is exit 0 `changed:false action:already_finished`; `--wait` timeout is exit 1 `wait_timeout`. A run stopped by a cancel request is stored `cancelled` and exits 1 ("agent run cancelled: cancel requested"), matching the existing cancelled→exit 1 vocabulary. `audit --max-cost-usd` / `--token-budget` are registered hidden and always rejected (exit 2) with the reason (drivers report usage only at the end). `audit --dry-run` prints `{driver, modes, audit_modes, piolium_modes, source, agent, sessions_dir, max_duration_ms, driver_check, interactive, note}` (emitObject, like autopilot's dry run); no clone, no session dir, no store. Error envelope gains top-level `agentic_scan_uuid` (contract.ErrorEnvelope mirrored). REST `POST /api/agent/scans/:uuid/cancel` for a run the server does not own returns 202 `cancel_requested` (404 otherwise, unchanged).

- VERB-2: `status` uses a local proxy seam `statusProxyResolver(cliProxy) (url, source)` (flag → HTTP_PROXY/http_proxy/HTTPS_PROXY/https_proxy, the order pkg/http's getProxyURL uses today); credentials redacted. Scope counts are non-default include/exclude counts per component from the global config (as `scope view` reads it).

- VERB-5: `NewUUIDListDBInputSource` alone does not restrict anything — the dynamic assessment reads the store through `RiskPrioritizedDBInputSource`. New `types.Options.RecordUUIDs` restricts that source (`WithRecordUUIDs`, param-shape coalescing off for named records); `scan --record-uuid` (repeatable StringArray, comma lists, 8+ char prefixes via `ResolveRecordUUIDInProject`) goes through the `--all-records` rescan path with `--only dynamic-assessment` unless `--only/--skip` were given. Evidence records (EvidenceRecordSources) are refused (exit 2) rather than silently dropped. Conflicts: -t, -T, -i, --all-records, -S, --db-isolate (exit 2). No `-u` shorthand on scan (decision 8's `-u` alias is FLAG-1, Wave 8). REST `POST /api/scan/records` now also sets `RecordUUIDs` — it assessed every project record before. Found and fixed a W1 regression: `RunNativeScan` dereferenced a nil admission (`admission.Admitted`) on any target-less scan (`--all-records` panicked).

- VERB-6: every new `--dry-run` reports through the mutation envelope (`dry_run:true`, `changed:false`) and keeps the command's normal item shape. `import --dry-run` performs the real import into a throwaway database (`dryRunScratchRepo`) so its counts are exact, never prompts (the bridge pre-flight confirmation is skipped), copies no session directory, and refuses `--format/-o` and `--upload` (exit 2). `ingest --dry-run` only parses (remote `-s` is ignored: nothing is sent) and adds `would_ingest`. `auth load --dry-run` never logs in (no request) and lists `{name, role, host, login_url, method, headers}` (header names only). `finding mark --dry-run` goes through new `FindingStatusUpdate.DryRun` (selectors resolved, no write). `db reset --dry-run` reports `files_removed` = files a real reset would delete. `config set --dry-run` via new `configcmd.Deps.WriteDryRunMutation`. Flags are registered from one table in `pkg/cli/dry_run_flags.go`.

- VERB-4: new sources `replay` and `fuzz` (`database.RecordSourceReplay/RecordSourceFuzz`) are in `KnownRecordSources` and `EvidenceRecordSources` (so scans, `--record-uuid` and `finding verify` baselines skip them). A single `replay` stores its exchange by default (`saved_record_uuid` on the item; human output prints "stored as record …"); bulk replay stores only with an explicit `--save` (a bulk re-send of 100 records would otherwise double the store) — deviation from "saves by default" for the bulk form. Nothing is stored with `--in-replace` (the source record is updated instead), `--with-browser`, `--read-only` or `-S` (`--once` reports `save_skipped`). `--once` = one send (no `--baseline`, not bulk/browser) printing `{record_uuid, saved, save_skipped, method, url, final_url, status, response_time_ms, content_type, response_length, body (16 KiB cap), body_truncated, error}` (schema variant `--once`). `final_url` comes from new `replay.Summary.FinalURL` (resp.Request.URL after redirects; empty via the Burp bridge sender). `fuzz --save` stores the results the run kept (`Matched`: matchers, or anomalies with `--anomaly`), `--save=all` every exchange, capped at 1000; via new `fuzz.Job.OnExchange` hook; summary extra `saved_record_uuids`. `replay --dry-run` (single source only; bulk is exit 2 pointing at `traffic`) prints the request that would be sent (schema variant `--dry-run`, envelope `dry_run:true`). replay.go/fuzz.go hunks are small (struct field, 5 call sites); the logic is in `pkg/cli/hand_send_save.go`.

- VERB-3: `config get` uses `FlattenSettings` with an exact-key lookup (a section prefix returns every key under it; a known key that flattens to nothing falls back to `SettingDisplay`), redaction as `config ls` (`--show-secrets`); unknown key exit 2 with `did_you_mean` (levenshtein). `config unset` deletes the key from the raw file via yamledit `Doc.Delete` inside `EditConfigFile` (comments kept; `--dry-run`); a key the file does not set is `noop`. New list op `<list>.remove <value|json list>` in `SetField`/`SetFieldEdit`/`SettingPath` (raw edit uses `Doc.RemoveItems`; when the file holds no list, the remaining default list is written). `scope add|rm <component> <pattern>... [--exclude] [--project] [--dry-run]` are `scope set <c>.include|exclude.add|remove <json list>`. `scope check <url>` uses new `ScopeMatcher.RejectDetail(host, path) (rule, pattern)` — exit 0 either way, `in_scope` says. `auth show <name> [--host] [--show-secrets]` and `auth rm <name> [--host] [--dry-run]` filter the project's session rows by name (not found → exit 1 `not_found`). `project current` → `{uuid, name, source}`. `project rename <ref> <new>` refuses a name another project holds (exit 2). `module show <id>` (exact, else a unique fuzzy match; several → exit 2 listing them). `finding show <id|hash>...` → finding views with records, `not_found` extra, exit 1 `finding_not_found` when any is missing. Config get/unset row types are mirrored in pkg/cli for the schema registry (configcmd cannot import pkg/cli).

- AGENT-2/N-6: "connection refused"/"no such host" stay in the shared transient list (a blip mid-run is still retried); the olium engine instead latches `connected` after its first successful call and treats a dial failure before that as terminal (`stream.ErrProviderUnreachable`, no retries). `pkg/agent` cross-call retry and the CLI classifier recognise the marker (by identity and by message, since provider errors cross the agent layer as text). The 2 s TCP dial (`agent.ProviderDialCheck`, via new `provider.Endpointer` on the Anthropic/OpenAI/Codex providers; dials the env proxy for the scheme when one applies; a provider with no HTTP endpoint or that cannot be built is skipped) runs in `agent query`, `agent triage`, `agent autopilot` and `agent swarm` before the preflight, whether or not `--no-preflight` is set; not in `Engine.Preflight` itself (REST callers keep the engine-level fast fail). New code `provider_unreachable` (exit 1); a preflight ping that fails on a dial error also reports it.

- AGENT-4: `requireInteractiveTTY(what, alt)` (/dev/tty opens AND stdout is a terminal; always refused under -j) gates the olium TUI (alt `-p`), the `agent triage` picker (alt `agent triage <finding-id>`; replaces the -j-only check) and `audit -i` (alt: drop -i). `agent query --stdin` reads stdin up front and refuses an empty/whitespace prompt (exit 2); `olium -p -` with empty stdin is now exit 2 too.

- SRV-2: machine mode = `-j` or new `--events [ndjson]` on `server`. It swaps `os.Stdout` for stderr for the command's lifetime (so the banner and every `fmt.Print` go to stderr) and writes one line on the real stdout after both listeners bind: `{type:"server.ready", schema_version, addr, url, pid, db_path, auth:"api_key|none", health_url, ready_url, ingest_proxy_addr, pidfile, ts}`. Fiber's access logger used `os.Stdout` captured at fiber's package init; `pkg/server/routes.go` now passes `Stream: os.Stdout` at route build time (same behaviour outside machine mode). Pidfile `~/.vigolium/server/<port>.json` `{pid, host, port, addr, db_path, auth, version, started_at}` is written after bind in every mode and removed on exit (only if it still names our pid). `/health` gains `pid` (additive; swagger regenerated). `server status [--port]` lists pidfiles with `process_alive`, `healthy`, `health_pid_matches`, `running` (+ `running` extra). `server stop [--port] [--timeout 40s]` signals SIGTERM only when /health answers with the recorded pid; a stale pidfile (process gone) is removed and reported exit 1 `not_found`; not exiting in time is exit 1 `wait_timeout`. Help documents /health and /ready; the API-key hint now says `--show-secrets`.
